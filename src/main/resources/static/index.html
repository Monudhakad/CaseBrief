About CaseBrief

What is CaseBrief?

CaseBrief is a document-processing utility for extracting labeled case information from CyberTipline-style PDF reports. It organizes selected fields into a consistent brief so a reviewer can find and check relevant details without repeatedly searching the full document.

The problem it solves

Finding the same details across long or repeated reports takes time. A structured brief groups extracted values under consistent fields, making records easier to scan, compare, and review alongside their source documents. It supports review; it does not make investigative decisions.

Upload modes

CaseBrief supports three input types:

  • Single PDF — process one report and view its extracted record.
  • Multiple PDFs — submit several reports together; each document is processed independently.
  • ZIP archive — process PDFs contained in one ZIP; non-PDF entries are ignored.

In a batch, a document that cannot be processed is reported as a failure; other documents continue. The system produces a structured Case Brief PDF for each successful document, plus a Summary ZIP, Excel workbook, and JSON processing status for batches.

Structured extraction

CaseBrief uses deterministic rules to match supported labels and values in each document. It does not use AI to interpret reports. Missing values are shown as N/A rather than filled in, and each document has its own result or failure record.

Documentation

Supported input types

  • PDF — one file or multiple files. The PDF must contain readable embedded text; scanned image-only files are not supported.
  • ZIP — an archive containing PDFs. Non-PDF entries are ignored.

Workflows

Single PDF

Choose a PDF, select Process PDF, review its result, then download the Case Brief PDF.

Multiple PDFs

Choose multiple PDFs, select Process Files, review each result, then download the available batch exports. A failure in one file does not stop the others.

ZIP archive

Choose a ZIP, select Process ZIP, review the PDF results, and download the available batch exports.

Output files

  • Case Brief PDF — structured fields for one successful document.
  • Batch Summary ZIP — successful Case Brief PDFs from a batch.
  • Excel workbook — a row for each successful record and a separate sheet for failed documents.
  • JSON status — structured details about successful and failed documents in the batch.

What happens when a document fails

A document that cannot be processed is listed with its filename and a failure reason. Other documents continue independently. Failed records are included in the JSON status and the workbook's failed-documents sheet; no Case Brief PDF is generated for a failed document.

Excel output — column guide

The "Case Brief Summaries" sheet contains one row per successfully processed document. Columns: Tipline No. (report ID), Suspect Name, Recent Suspect IP, Geo City (highlighted in red), Priority, Reporting ESP, Incident Type, Suspect Age/Phone/Username, Recipient Name/Age/Phone/Username, Content Rating, Geo Postal Code. Fields that were not found in the source document are shown as N/A.

JSON status output

The batch status JSON contains successfulRecords and failedRecords arrays. Successful records contain extracted fields; failed records contain available document identifiers and a failure reason. Use it to review processing outcomes or as structured input to another tool.

Limitations

  • Image-only or scanned PDFs are not supported — extraction requires embedded text.
  • Extraction accuracy depends on the document following a recognizable CyberTipline-style structure. Non-standard formats may produce incomplete results.
  • Missing fields remain N/A. No value is invented or inferred when a field is absent.
  • CaseBrief does not verify, validate, or cross-check extracted data against any external database.
  • The generated Case Brief PDF is a formatted output of what was extracted — it is not an investigative conclusion.

Privacy

Document handling

When you submit a document, your browser sends it to the server hosting this CaseBrief instance for processing. The hosting environment and its configuration determine how uploads, temporary files, logs, backups, and generated outputs are handled. CaseBrief does not promise encryption or automatic deletion of uploaded data.

Feedback submissions

Feedback submitted through the form is saved by the application to a file on the server. Name and email are optional. Consider this when using a shared or public deployment.

Third-party requests

The page stylesheet imports fonts from Google Fonts, so opening the page may request font resources from Google. Review the deployment's network and privacy requirements before use.

Demonstrations and sensitive information

Avoid uploading real sensitive documents to an untrusted or public deployment. Use synthetic or redacted data for demonstrations. Only upload documents you are authorized to process, and confirm the server's handling practices with its operator.

Deployment responsibility

Privacy and security depend on how and where CaseBrief is deployed. Do not assume that any certification or particular security control applies unless the deployment operator confirms it.

Terms & Disclaimer

Purpose and limits

CaseBrief is a document-processing and summarization utility that organizes information extracted from PDFs for review. It is not an investigative decision-making system, a legal advice system, or a replacement for human review. It does not independently determine guilt, violations, or investigative priority.

Review the source

  • Extracted information may be incomplete or incorrect.
  • Review all extracted information against the original source document.
